## Run and test

Prerequisites: Java 21 and Maven. From the repository root:

```sh
mvn -f backend/pom.xml verify
cd backend
java -jar target/achillea-0.1.0.jar
```

Backend binds `127.0.0.1:8080`. Launch from `backend` so the default H2 path remains `backend/data/achillea`. Starting elsewhere changes a relative database path. An absolute DATABASE_URL is recommended if using multiple launchers.

## Server configuration

Environment variables (export in shell; no dotenv loader):

| Variable | Default | Purpose |
|---|---|---|
| APP_DEMO_MODE | true | Gates record and simulation APIs; also disables scheduler when false |
| DATABASE_URL | jdbc:h2:file:./data/achillea | Persistent local synthetic dataset |
| MONITOR_SIMULATION_ENABLED | true | Periodic simulated arrivals; false for controlled recordings/tests |
| MONITOR_CADENCE_MS | 15000 | Delay between completed monitor cycles |
| MONITOR_INITIAL_DELAY_MS | 15000 | Startup delay before first cycle |

No hardware or AI credentials are required. Use a positive monitor cadence. The simulator is a local, single-process educational demo. Keep it bound to loopback; no hospital authentication or physical integration is added.

## Existing databases and reset

Normal restart preserves all saved tasks, charts, amendments, events and original patient IDs. It never reseeds an existing dataset or shifts historical timestamps. Legacy snapshots get additive in-memory device metadata, persisted with the next command. To load the expanded census, deliberately POST `/api/demo/reset` (the existing UI Reset control does this). Reset discards only this local synthetic demo aggregate; do not use real data.

Reset uses an injected UTC Clock, fixed scenario definitions, stable seed IDs, and present-relative times. It creates 10 L&D + 7 ICU census patients, 3 assigned in each unit, 51 tasks overall (30 L&D / 21 ICU), over 100 real historical activity records, and 31 points per supported metric per patient across an hour. Retained original IDs include synthetic-ld-01/02, synthetic-icu-01, task-1/2/3/4. New UUIDs identify actions after reset.

Fresh reset has past-due reviews, upcoming reviews around 15 minutes, routine documentation around 90 minutes, historical completed tasks, acknowledgments, and deferrals. Time continues to pass: restarting hours later correctly leaves old tasks overdue rather than silently rewriting the shift. Reset explicitly starts a new present-relative demo.

## Simulator semantics

The default monitor cycle runs every 15 seconds and emits HR, SpO2, respiratory-rate observations from stable patient/device mappings. Smooth HR waves and bounded synthetic SpO2/respiratory steps illustrate trends; no thresholds are represented as clinical guidance. No new diagnosis, verified chart, or care completion is generated by a tick.

Automatic device cycles are deterministic: over a 40-cycle period each monitor has two disconnected cycles and one delayed cycle, staggered by patient. Manual disconnect/delay/reconnect overrides that automatic connection cycle until reset. Disconnected monitors emit no readings; reconnect emits a fresh reading; delayed samples preserve their older sample time. Sensor heartbeats preserve observed region angles and create samples, not turn candidates. Sensor disconnect stays unknown through subsequent motion until explicit reconnect.

Observations retain up to 360 points per patient/metric plus every chart-linked observation. Sensor sample retention keeps 360 recent points per sensor plus all candidate references. Activity retains 4000 most recent events. This is a bounded demo window, not production audit retention. JPA persists a single versioned aggregate; synchronized commands commit one repository transaction before releasing the service lock. It is not a multi-server clinical database.
